# SDK subagent delegation on Replicated — 2026-07-26

## Outcome

The tested Replicated user setting persisted `enable_sub_agents=true` with
`tool_concurrency_limit=1`, but a newly launched V1 app conversation did not
receive the SDK task tool in its system prompt. Its event stream contained zero
`TaskAction` and zero `TaskObservation` events.

This is an integration gap, not a successful subagent benchmark. Do not use
the observed latency or cost as evidence of TaskToolSet performance.

## Why this is a separate execution pattern

The current OpenHands SDK TaskToolSet creates a subagent beneath one parent,
blocks the parent until the child returns, persists the child conversation, and
supports resuming it by task ID. The default is sequential execution.

The supplied Agent Canvas SDLC recipe uses a related parent/child organization,
but its parent creates separate child Canvas conversations through the local
agent-server API. Enterprise external orchestration likewise creates
first-class app conversations. Those are conversation-delegation patterns, not
native TaskToolSet events.

Primary references:

- <https://docs.openhands.dev/sdk/guides/task-tool-set>
- <https://docs.openhands.dev/sdk/guides/parallel-tool-execution>
- <https://github.com/rajshah4/sdlc-automation-github-demo/tree/main/agent-canvas>

first-class conversation orchestration or Agent Canvas for trusted shared
work—not SDK subagents on this Replicated profile.
