# Kaggle NeuroGolf parity review

This project now reproduces the **organization around a NeuroGolf campaign**:
task ownership, bounded parallel work, independent validation, promoted memory,
immutable evidence, recovery, and cleanup. It does not yet reproduce the
competition's ONNX workload or claim a competitive Kaggle score.

That distinction matters. “Production-grade orchestration” and “top Kaggle
solver” are separate claims, and both need evidence.

## What public NeuroGolf teams actually built

Public writeups and licensed repositories converge on a recognizable pattern:

- one task owner per worker;
- persistent task state, attempts, failures, and negative knowledge;
- a scheduler that protects coverage before spending heavily on promising
  tasks;
- candidate branches that are promoted or rejected after validation;
- official examples plus independent, generated, adversarial, or metamorphic
  tests;
- a serialized release path for assembling and checking the 400-task archive;
- different agent interfaces for high-throughput search and long-context
  semantic review.

  (Apache-2.0)

The Apache-licensed reference was checked at commit
`5a02fee`. On a clean Apple Silicon checkout, 24 tests passed and three were
skipped because optional build/fuzz assets were absent. Ruff passed. The full
frozen installation could not build `pyeda==0.29` on that platform, and the
repository's scratch tooling produced 24 type diagnostics. This is a useful
reality check: competition-quality research code can be excellent at the
domain problem without being a turnkey production service.

## Parity matrix

| Capability | This project | Public competition pattern | Status |
| --- | --- | --- | --- |
| One owner per task | Scheduler records every selection and ownership | One task per worker | Proven |
| Coverage before repeated search | Managed scheduler balances attempt counts across tasks | Coverage-aware schedulers | Proven |
| Immutable attempt history | Append-only manifests, decisions, lifecycle, attempts, and reports | Task state and attempt logs | Proven |
| Validated shared memory | Lessons enter retrieval only after deterministic validation | Positive and negative knowledge | Proven |
| Restart recovery | Same run/attempt resumes and reattaches to persisted OpenHands start task | Watchdogs and persistent task state | Proven |
| Capacity control | Launch gate, bounded concurrency, pause-on-finish | Worker and memory guards | Proven on one Replicated instance |
| Large campaign bookkeeping | 400 tasks, 4,800 attempts per arm, 9,600 total | 400-task competition | Proven as deterministic orchestration simulation |
| Independent domain validator | Graph coloring, set cover, and bin packing validators | ONNX execution and ARC equality | Different workload |
| Candidate artifact pipeline | JSON candidates and evidence hashes | ONNX, builders, docs, fuzz corpus | Not yet |
| Adversarial validation ladder | Exact deterministic examples | Official, synthetic, adversarial, metamorphic | Not yet |
| Submission quarantine | Report generation only | Serialized archive audit and manual submission | Not yet |
| Multiple controllers | Deliberately rejected by a file lock | Leased distributed workers | Not yet |

## The measured scale and robustness result

The local 400-task matched simulation ran 4,800 attempts in each arm:

| Metric | Naive independent | Managed organization |
| --- | ---: | ---: |
| Tasks receiving work | 400/400 | 400/400 |
| Attempts per task | 12 | 12 |
| Normalized final quality | 0.6675 | 1.0000 |
| Quality AUC | 0.6397 | 0.9582 |
| Validated lessons available | 0 | 14,394 retrievals |

These numbers validate scheduling, ledger, retrieval, and measurement behavior.
They are generated by deterministic workers and **must not be presented as
model or Kaggle performance**.

A separate 4,800-attempt single campaign completed in 19.08 seconds, retained
24,013 parseable JSON records in 94 MB, and preserved unique attempt IDs and
sequences. The previous implementation took 569.78 seconds; indexed run state
and cached lessons made the hardened path about 29.9× faster.

## Live failure recovery

On the Replicated Enterprise installation, the controller was killed after
OpenHands created a start task but before the attempt completed. Restarting
with the same run ID:

1. acquired exclusive file-store ownership;
2. found the incomplete attempt and persisted start-task ID;
3. reattached instead of creating a second conversation;
4. retrieved and validated the final answer;
5. recorded one completed attempt; and
6. paused the sandbox.

There was exactly one `start_task_created` event and one OpenHands conversation.
This is the minimum evidence needed to call the files-first pilot restartable.

## What “at Kaggle level” requires next

Use an Apache-2.0 or MIT-licensed public solution as a workload reference, but
keep this repository's orchestration independent. Do not copy unlicensed
solution dumps.

The next benchmark should add a `NeuroGolfWorker` and `NeuroGolfValidator` that:

1. check out one task's builder, model, and documentation into an isolated work
   unit;
2. execute the official ARC cases through ONNX Runtime;
3. run fresh generated, adversarial, and metamorphic cases;
4. calculate the competition memory-plus-parameter score;
5. quarantine the candidate until every gate passes;
6. store the ONNX artifact, builder, logs, counterexamples, and hashes; and
7. allow only a single release process to assemble and audit the submission.

Until that adapter passes licensed reference tasks and produces an independently
scored archive, the correct claim is:

> We reproduced and stress-tested the multi-agent research organization used by
> serious NeuroGolf teams. The domain-solving layer is the next benchmark.
